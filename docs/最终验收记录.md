## 发现并修复的问题

- Windows fastText原生路径/NumPy兼容：独立运行时与ASCII临时IO，未混装原环境。
- Vite8分包接口变化、vendor CSS覆盖主题色、长工单号撑行、审核状态标签不可见：均修复并重跑生产页面。
- 快速切换工单可能收到旧请求结果：加入序号核对并清空旧详情/草稿，后端资源权限仍是最终防线。
- 模型说明文件被格式化导致哈希不符：阻止加载，恢复固定官方版本、保留修改件排查，排除产物目录；没有改清单绕过校验，未改变模型权重。
- Linux跨平台依赖解析漏hf-xet：在CPU检索依赖显式声明并补齐wheelhouse，CPU镜像构建与真实检索已通过。
- Docker网络DNS/无路由、镜像站TLS超时及引擎反复500：保留失败日志，用官方来源的Linux wheelhouse离线构建；暂时隔离原27个容器后完成整栈实测。曾观测内存约96%，没有将资源压力认定为已证实根因。
- 先前引擎中断留下仅含系统表的MySQL半初始化卷：脚本核对项目标签、精确数据卷、空口令本地root和无业务库后补全初始化，未删除或重置卷；后续正式迁移成功。证据docker-partial-init-recovery.json和docker-migration-final.log。
- 开发Swagger页面被主站CSP阻止加载：仅非生产/docs允许其官方CDN资源，主站与生产仍使用严格策略；106项早批次和当前111项回归均包含隔离断言。
- 本地冷启动API先于模型服务就绪，首次检索曾返回503：启动脚本改为同时等待API就绪与模型服务认证健康检查，随后再次重启并执行真实检索；失败报告保留为local-runtime-first-after-restore.json。
