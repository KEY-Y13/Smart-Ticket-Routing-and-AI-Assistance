# 本地模型运行时与重建方式

## 当前实测组合

| 环境 | 用途 | 关键版本 |
|---|---|---|
| `.conda` | API 基础、数据、RF/LR、编排、基础测试 | Python 3.12.16、NumPy 2.5.4、sklearn 1.9.1 |
| `.venv-fasttext` | 独立 fastText worker | fasttext-wheel 0.9.2、NumPy 1.26.4、psutil 7.2.2 |
| `.conda-bert` | 本地 safetensors BERT smoke、ML 专项测试 | torch 2.5.1+cu121、Transformers 4.57.6、NumPy 2.5.4、psutil 7.2.2 |

项目内隔离环境可修改；原课程环境和数据库未修改。不改全局 PATH、系统代理、执行策略或显卡驱动。

第三方 fastText wheel 在当前机器实测通过，不能推广为官方 Windows 支持。BERT 环境使用缓存的官方旧 wheel 是为了完成本地复现，**正式部署仍须重新选择维护版本并验证**。所有模型部署审批为 false，不加载外部 pickle 权重，不运行远程模型代码。

## 网络和依赖问题的实际处理

1. 继承代理导致 PyPI/下载源 TLS EOF；仅安装子进程移除 HTTP_PROXY/HTTPS_PROXY/ALL_PROXY，保持证书校验，不改全局设置。
2. torch 2.14.1+cu126 元数据可读，但大文件下载不稳定，已停止该新建下载进程，不声称安装成功。
3. 本地旧 wheel 的 SHA-256 与官方索引完全一致：`473d76257636c66b22cbfac6f616d6b522ef3d3473c13decb1afda22a7b059eb`。复制到项目后安装，新文件与来源记录在 artifacts/wheels/。
4. 曾尝试 ML 环境 NumPy 1.26.4，实际 pip check 发现 SciPy 1.18.1 要求 NumPy≥2，因此恢复 2.5.4。GPU 运算及 Tensor→NumPy 桥接均实测通过，最终三环境 pip check 全通过。没有忽略依赖冲突。
5. `.conda-bert` 的 Torch 为旧版，只用于本机受控 safetensors 训练验证；新版驱动/运行时和正式部署依赖验收单列未完成。

## 新机器重建（不是在现有环境上覆盖）

先按 README 建好基础 `.conda`，确认目标 ML 前缀不存在，再执行：

```powershell
& '.\.conda\python.exe' -X utf8 -m venv .venv-fasttext
& '.\.venv-fasttext\Scripts\python.exe' -X utf8 -m pip install -r requirements-fasttext-win.lock
& 'E:\heima\software\Anaconda\Scripts\conda.exe' create --prefix 'E:\AI_project\SmartTicket-AI\.conda-bert' --clone 'E:\AI_project\SmartTicket-AI\.conda' --offline --yes
& '.\.conda-bert\python.exe' -X utf8 -m pip install -r requirements-bert-local-win.lock
```

锁文件含官方 Torch wheel URL 与 SHA-256。下载可能受网络影响，不自动关闭证书校验或改安装源。此锁仅复现已验证本地 smoke，不代表推荐生产使用旧版。

BERT 资产以 `google-bert/bert-base-chinese` 固定 revision 的 safetensors + tokenizer 为准；本机从原只读 HF cache 复制，没有重复下载权重。用 `prepare-bert-assets --source <该revision缓存目录> --out <新目录>` 导入；重复目录拒绝覆盖。其他机器应从官方仓库明确下载同 revision 后再校验，程序不会偷偷联网。

## 运行与验证

```powershell
.\scripts\check.cmd
& '.\.conda-bert\python.exe' -X utf8 -m pytest -q tests_ml
.\scripts\run_models.cmd --device cuda --epochs 1
```

完整实验脚本新建时间戳目录，共用同一 split manifest，依次运行 RF/LR、fastText、BERT，最后检查数据/切分/标签/用途一致才合并。单阶段失败保留日志并停止，不展示部分结果为全对照完成。

第三批后端依赖只加入基础 .conda，未修改 ML 环境。当前完整后端/基础测试用 scripts/check.cmd，ML 专项用上方 tests_ml。第二批历史“61 passed”为当时实际执行范围，不自动累加为当前全平台验收。

后续RAG模块在项目ML环境新增FAISS CPU 1.15.1和SentencePiece 0.2.3，精确快照为requirements-rag-local-win.lock；未修改原toumanfen等环境。BGE模型和Reranker固定官方revision及哈希，CPU线程4、重排batch4；模型服务8011与API8010用独立私有令牌通信。

宿主机与Docker环境不可混用：Docker离线wheelhouse由Windows下载Linux CPython3.12 wheel并校验，未在Windows安装。CPU检索镜像用Torch2.10.0+cpu，额外声明Linux条件依赖hf-xet，避免跨平台解析漏包。构建产物目录排除格式化，防止模型卡被修改导致来源哈希校验失败；不通过改清单绕过校验。

2026-11-07成功容器的完整pip快照为requirements-docker-app-linux.lock和requirements-docker-retrieval-linux.lock；对应wheelhouse有SHA-256来源清单，构建与真实运行证据见最终验收记录。它们是Linux运行快照，不覆盖Windows锁文件。本地启动会等待API和模型服务认证健康检查；模型权重惰性加载，首次实际检索仍有冷加载耗时。

当前 BERT 默认 length=128、batch=2、累积=4、FP16、checkpointing；无 CUDA 会明确报错，不静默换 CPU。`--device cpu` 是显式选择，时间和资源需另测。

工作区临时 IO 位于 artifacts/native-workspaces，路径必须 ASCII；用于解决旧 fastText 原生 Windows 路径限制。最终实验输出可包含中文目录。
