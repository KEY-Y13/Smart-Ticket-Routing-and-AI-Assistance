# 业务理解与可选独立复刻

2026-11-10用户已调整目标：代码实现、修复、测试由AI负责，用户重点理解业务逻辑，不再把“本人从零复刻”作为当前交付要求。生产环境暂不推进。原first_project仍保留不改动。

当前讲解按一条工单展开：客户提出什么诉求→为何归到该类→为何派给该客服→订单事实从哪里查到→政策依据是什么→为何回复仍需审核→何时解决/关闭/重开。用户不必逐行背代码或完成编程作业。

业务理解重点：故障诊断与明确退货诉求的区别、付款问题与退款到账的区别、资源授权与客服技能的区别、草稿与已发送回复的区别、模型分数与业务正确性的区别。每次改动用实际案例解释触发条件、处理过程和失败结果。

## 旧版独立复刻路线（仅供以后自选）

以下路线保留作可选学习材料，不计为当前项目的未完成项。只有用户以后选择独立编码时，才恢复先设计、分层提示、审查代码的辅导方式；不会擅自修改原课程目录。

| 顺序 | 用户应独立产出的东西 | 黑盒验收要求 |
|---|---|---|
| 1 | 工单实体、状态转换与权限设计 | 客户不能读他人工单，非法转换被拒绝 |
| 2 | 数据库迁移、认证与事务接口 | 空新库可迁移；并发版本冲突；重放不重复创建 |
| 3 | 标签规范、数据检查与传统基线 | 测试集不参与fit，分组不跨切分，保存错误样本 |
| 4 | BERT训练循环 | 解释每个张量维度、CE、梯度更新、保存/重载 |
| 5 | 派单与SLA | 最后容量竞争无超卖，重启扫描不重复提醒 |
| 6 | 文档版本、Embedding、混合检索 | 旧知识失效；四路同集评估；能区分召回和排序失败 |
| 7 | 草稿反馈与受控业务查询 | 没证据拒答、没权限拒查、没审核不发送、旧草稿拒发 |
| 8 | Vue联调、部署与讲解 | 真实接口闭环、错误/空状态、恢复演练和诚实实验结论 |

每个模块先写最小可运行路径再加错误边界。可以查框架文档和参考API风格；数据切分、状态不变量、训练循环、检索融合、证据时效和事务边界应能自己解释并独立写出核心部分。

起始需求只需是：“为客户创建和查看自己的售后工单，设计最少字段、合法状态以及资源权限。”此阶段先讨论设计，不立即展示参考实现。已看过参考代码不等于掌握；延迟复述、换场景解释和独立排错才是更强证据。

完成后记录真正暴露的薄弱点，在后续模块自然复习；被提示后的正确答案不视为独立掌握。所有正式数据标注仍要按来源、许可、相似去重和独立复核标准，不能为凑规模自动把合成文本标为人工审核。
