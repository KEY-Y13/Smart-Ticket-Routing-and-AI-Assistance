# NLP 数据契约、切分与审核

## 当前范围

已实现 `nlp/data/schema.py`、`dataset.py` 和 `nlp/labels.py`。当前 72 条全部为 AI 编写的合成样例，未人工复核，仅允许 `--purpose smoke`。300–600 条人工试点与 1,200–3,000 条正式目标尚未完成。

## 标签

0 订单、1 支付、2 物流、3 售后退款、4 商品质量、5 账户，版本 `six-primary-v1`。类别是主要需要处理的诉求，不是文本中出现的关键词。

- 商品故障诊断：质量；明确请求办理退货：售后退款，故障作为原因。
- 普通扣款/支付失败：支付；已经发起退款后的到账进度：售后退款。
- 下单与修改收货资料：订单；已发货运输轨迹：物流。
- 多诉求/歧义文本进入人工复核，不强制塞入某类。当前单标签数据契约只接收可标定的案例；歧义待审池与业务分析结果后续单独实现。

## 输入输出与维度

输入为每行一个 `TicketSample` 的 UTF-8 JSONL。字段包括文本、标签、sample_id、group_id、来源类型/引用/许可/权利状态、复核状态和 reviewer。拒绝未知字段，避免把客户手机号等附加字段混入训练数据。

`prepare_manifest` 输出 JSON 清单：原文件与数据哈希、标签哈希、种子、来源统计、分组、三个切分的 sample_id 和每类计数。不会训练或调用模型。

## 防泄漏

1. 人工将同一对话、模板、改写、生成场景种子放入同一 group_id。
2. NFKC + casefold + 标点/空白清理；屏蔽长编号，保留短的政策时间数字。
3. 相同归一化文本及字符二元组 Jaccard≥0.82 的文本合并，取传递闭包。同组标签冲突时报错。
4. 在每类内部按组切分，近似 70/15/15；每类每组至少有独立样本来源，至少三组才能形成三个集合。小数据比例会受组数约束。
5. 在只看标签计数的 128 次组排列中选择数量较平衡的切分；此过程不看模型结果。正式集合生成后锁定。
6. 训练前重新算数据哈希、归组、集合覆盖/互斥和标签完整性，防止改了数据仍复用旧清单。

词面检测复杂度 O(N²)，目前目标几千条可测量评估；更大规模再改候选召回，不提前增加系统。该算法不能发现所有同义改写，不能证明语义无泄漏。

## 审核流程

原始候选 → 人工独立标注 → 歧义复核 → 确认来源与使用范围 → 记录实际 reviewer → 新版本清单。不能把 AI 自动给出的标签直接设为人工已确认。外部数据的代码许可证和数据使用授权分开查。

`formal` 拒绝未批准/权利未知/完全重复记录；`smoke` 也拒绝 rejected 样本。`project_internal` 只表示本项目内部使用，不是对外开源许可。程序检查 reviewer 非空无法证明审核真的发生，必须依赖审核记录。

## 单独运行

在项目根目录，使用项目 `.conda/python.exe -X utf8 -m nlp.cli prepare --data data/samples/classification-smoke.jsonl --purpose smoke --out data/processed/自己的新清单.json`。输出已存在会报错，不覆盖。

正式使用同命令换 `--purpose formal`，当前原始样例应被拒绝。`tests/test_dataset.py` 验证数据变更、相似组泄漏、标签冲突和审核门槛。

## 易错点和面试追问

- 为什么新闻数据的十类模型不能直接拿来做售后六分类？标签语义和分布都不同。
- 随机切分为何泄漏？同源改写可能落在不同集合，模型只需记模板。
- 为什么 TF-IDF 也会泄漏？全量 fit 会利用测试词项统计，必须仅 fit 训练部分。
- 哈希证明了什么？证明给定清单和输入的一致性，不证明数据质量或合法性。
- 为什么小样本高分无意义？类别覆盖、模板独立性和置信区间都不足，不能外推业务效果。
