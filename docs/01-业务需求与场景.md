# 业务需求与场景

本项目为虚构3C电商售后参考系统。客户、订单、支付、物流、退款记录及50篇政策均为演示数据；系统查询已授权的固定业务字段，不执行真实退款，也不把模型推断写回交易来源表。

## 一条真实执行的业务路径

客户提出“蓝牙耳机一侧无声”，可关联本人演示订单。创建接口在同一事务保存工单、首条公开消息、SLA周期、事件和分类任务，先保证问题被记录。后台分类失败、模型未配置、分数未达阈值或审批已撤销时进入人工复核；不凭空填入分类。

管理员确认六类之一，依据技能组、在线状态、容量和规则优先级派单。类别映射与哈希以nlp/labels.py为准。没有合适客服时保留等待队列及具体原因，管理员可以按优先级/创建时间取下一单；系统没有宣称持续自动重派全部等待工单。

获派客服进入工单，另经技能组的业务查询权限读取演示订单、商品快照、支付/物流/退款状态。客户文本中的订单号只是候选，必须经过当前用户和工单资源授权查询，才能成为业务事实。

客服可生成证据摘录，或在付费开关及余额允许时生成百炼草稿。检索执行BM25、向量、RRF与重排，过滤失效政策；没有充分依据则拒答。草稿保存版本化原文引用、上下文指纹、输入版本和用量，不直接发给客户。审核人采纳、修改采纳或拒绝后，另行发送；发送前再次检查权限、工单/知识版本和状态。新增消息或政策失效可能使旧草稿不可发送。

完成回复后解决、关闭；七日内重开产生新SLA周期，历史提醒及审计保留。等待客户、等待外部协助不停表。自动回执、内部备注和未发送草稿不计首次响应。

## 权限边界

| 身份 | 可以执行 | 关键限制 |
|---|---|---|
| 客户 | 创建、读取本人公开工单；补充公开消息；允许范围内关闭/重开 | 不能读取他人工单、内部备注、运行指标或来源交易表 |
| 客服 | 处理当前获派工单、内部协作、证据草稿、审核发送与解决 | 业务查询还需要技能组can_view_business；不能自行选择其他客户订单 |
| 管理员 | 人工分类/派单、SLA政策及提醒、知识版本、用户/技能组/规则、样本复核和模型审批、运行状态 | 管理权限不等于允许真实资金操作；数据和模型审批仍需要实际审查 |

所有接口以后端角色与资源归属为准。前端隐藏按钮只是交互提示。JWT留在页面内存，退出撤销；业务变更需要版本，创建使用幂等键。派单在数据库互斥与事务中重查最后容量，保留分配事件。

## 正常流程以外必须保留的结果

| 情况 | 系统应给出的真实结果 |
|---|---|
| 订单不存在或不属于当前客户 | 明确拒绝，不把相似编号当事实 |
| 没有规则、没有技能、客服离线、容量已满 | 保留工单与相应等待原因，不显示假成功 |
| 未批准模型、损坏模型或撤销审批 | 人工分流；影子包保留候选分数而不自动派单 |
| 检索无依据或政策过期 | 拒绝生成/发送不受支持回复 |
| 百炼鉴权、额度、超时或输出验证失败 | 明确失败；失败已预留调用仍计额度，不自动付费重试 |
| 同版本并发修改/复核 | 一个版本只能生效一次，其余返回409要求刷新 |
| 后台/检索停止 | 管理员运行状态可发现故障；恢复后按持久化任务和SLA记录继续 |

## 数据与模型许可

现有分类72条、政策50篇、检索110条、真实百炼50例已归入四类候选复核批次，总282条。全部仍待独立人工复核。按原需求“找不到足够适用数据时先缩小训练范围、完善标注流程”的允许路径，四模型使用同一72条smoke集验证工程；没有凑成1200条重复模板，也没有把合成数据自动认作人工审核。

管理员可逐条标注并冻结不可变JSONL，正式模型再绑定来源、复核版本、数据/切分及产物哈希。影子模式保持人工；正式自动分流要求至少1200条已复核数据和独立测试/质量门槛。详见20-数据复核与模型审批.md。

## 交付范围

原始需求的P0/P1参考功能、测试、文档和部署以最终15项验收表逐项追溯。多租户、Kubernetes、真实退款、多平台接入、多智能体、在线自动训练、OCR/语音仍属于明确暂不实现的P2。阶段B是用户本人独立复刻，与阶段A参考代码和原first_project隔离；不因“继续项目”而代写学习成果。

代码入口：services/tickets.py、business.py、assistant.py、knowledge.py、jobs.py、reviews.py、operations.py；运行入口scripts/start.cmd。完整浏览器用例frontend/e2e/workflow.spec.js，权限/状态/失败分支见tests/backend，真实数据库竞争见tests_mysql。
