## 日常使用

本机入口http://127.0.0.1:8010；管理员、客户和客服的随机凭据只在.mysql-local/login-info.txt。启动scripts/start.cmd，停止scripts/stop.cmd。MySQL仅为本项目33307实例；原3306不改动。参考项目位于E:\AI_project\SmartTicket-AI，原first_project保留。

“数据统计”新增运行状态：业务库、后台心跳、检索健康和当前索引；另显示队列积压、过期租约、失败任务、百炼已预留/剩余次数以及当前API进程的请求和延迟采样。刷新只读取服务健康，不执行检索推理或模型调用。快速切页时过期请求不再初始化已经卸载的图表。

后台每轮写同目录原子替换的心跳文件。默认180秒过期，正常周期30秒；故障告警有配置窗口，不能声称进程一停立即识别。正在执行的周期可以在线，长任务超过心跳窗口也需人工排查。异常只记录类型，不保存异常中的客户内容或密钥。API请求计数从进程启动累积，延迟用最近1000次请求的nearest-rank P95，重启后归零；不是分布式遥测或百炼推理延迟。

```powershell
# 仅本地输出状态变化与JSONL，不向任何外部联系人发消息
.\.conda\python.exe -X utf8 -m scripts.monitor_local
.\.conda\python.exe -X utf8 -m scripts.monitor_local --watch-seconds 300 --interval 30
```

状态正常退出0，有待处理告警退出2。当前百炼54/60、余6次，达到10%低额度提醒阈值；这条提醒不表示数据库或后台故障。已预留的失败/未知调用也占预算。不要为消除提醒自动提高付费额度。日志artifacts/services/operations-alerts.jsonl仅在状态/提醒变化时追加，外部通知、保留周期与企业监控平台未冒充已经部署。

## 已验证的故障与负载

scripts.verify_operational_recovery只中断核验过可执行文件和模块的本项目worker/检索；不停止原MySQL或其他应用。它不修改心跳时间造故障，而是真停worker等待180秒窗口，再停检索检查、最后在finally恢复服务。本轮约181秒发现失联，API继续可用，组件恢复与百炼调用数不变均通过。此脚本有实际短暂停机，不用于没有维护窗口的生产服务。

scripts.load_sustained在本机300秒按5RPS、最多4个在途请求读取健康、工单列表和业务统计。预先门槛为全200、P95<1500ms、实际速率≥计划90%、付费调用不变。本轮1500请求全200，约5.00RPS，P95约32ms。实测报告含每次耗时、调度滞后和内存采样。这是本机核心读取能力，不是公网、多用户持续生产容量、向量重排并发或百炼吞吐。

统计接口原先对每张工单和每条审核反馈重复查询。现将历史派单按工单分组计数，审核反馈与建议一次关联读取；专门测试确认0条和20条工单/反馈的SELECT次数保持一致、上限10次，同时保持统计分母和重派结果。不能把不同并发/环境下旧P95与新P95直接做百分比收益宣传。

## 可选本机HTTPS

```powershell
.\.conda\python.exe -X utf8 -m scripts.local_https start
.\.conda\python.exe -X utf8 -m scripts.verify_local_https
.\.conda\python.exe -X utf8 -m scripts.local_https stop
```

独立监听127.0.0.1:8443；生成30天本机测试CA与localhost/127.0.0.1证书，私钥仅写受ACL保护、被忽略的.tls-local。验证实际TLS握手、证书链、主机名、认证接口；不信任的CA和错误主机名均被拒绝，全程没有verify=False。不会安装系统信任、开放公网或替用户购买证书。浏览器没有手动信任本机CA时出现证书提示是预期边界，默认日常入口仍为8010。本机测试CA不等于企业域名的公开可信证书。

依据：[cryptography X.509教程](https://cryptography.io/en/latest/x509/tutorial/)；[Python SSLContext及证书验证](https://docs.python.org/3.12/library/ssl.html#ssl.create_default_context)。源码scripts/local_https.py与verify_local_https.py。企业公网部署仍需自己的域名、受信证书、网关策略、目标SLO、密钥/日志保留与运维责任。

## Docker运行边界

独立Compose项目smartticket-ai，端口8012；MySQL卷和检索索引卷保留，仍默认禁用付费。governance_data由API写发布包、worker只读；operations_data由worker写心跳、API只读。worker健康检查读取新鲜心跳。真实容器验证拒绝反向写入，并检查重启后数据库、索引和发布包内容。

构建、就绪、源文件/镜像哈希、浏览器、真实重排、最小权限、重启及新卷恢复各有独立报告，不能用compose config代替运行。恢复仍使用新卷/新库，不覆盖旧数据。验收后关闭Desktop并恢复原容器启动状态；日常本机运行不依赖Docker。

## 可移交源码包

```powershell
.\.conda\python.exe -X utf8 -m scripts.package_release
.\.conda\python.exe -X utf8 -m scripts.verify_release_package
```

包位于artifacts/releases，具体文件及SHA-256见artifacts/validation/release-package.json。使用明确白名单：源码、构建网页、前后端测试、文档、虚构参考数据和指定实验报告。包内RELEASE-MANIFEST.json记录每个成员哈希；逐文件检查配置密钥与私钥，拒绝越界链接。

不包括.env、数据库目录/转储、.docker-secrets、.tls-local、Conda/venv、node_modules、下载权重或所有离线wheel。提取到全新临时目录后，在移除真实API配置、LLM禁用、临时SQLite的条件下执行后端业务测试。它证明源码包没有依赖原数据库来通过这些测试；仍复用本机已装依赖，不冒充一台干净机器完整重装。模型与环境重建见环境与实验运行.md；Linux离线包另按15-Docker部署.md准备。

1. scripts.validate：依赖、Ruff、默认回归、JUnit与源码指纹。
