## 逐条复核

1. 选择批次与状态，阅读原始内容，先独立选择标签；原标注默认隐藏，可展开参考。
2. 分类需要标签、同源分组与数据权利；可提交修正文案。原始文本不会被覆盖。同一对话、改写及近似样本应属于同组，随后仍执行相似归组与固定切分。
3. 政策记录演示场景可用/不适用/无法确认。检索记录是否可回答，以及确实存在的相关文档标识。拒答时相关文档应为空。
4. 百炼案例展示已保存草稿、原证据和拒答信息；拒答正确性必须与可以接受/错误/无法判断保持一致。没有保存完整输出的案例仍显示证据局限。
5. 实际复核人填写至少5字理由，明确勾选亲自核对，再确认或排除。后端从登录身份记录审核人，拒绝客户端伪造身份；版本冲突返回409，须刷新再核对。

“已确认”表示复核判定已保存，不代表所有知识或LLM回复都正确；标注仍可能为不适用或无法判断。复核不会直接发布知识版本、修改客户回复、触发训练或资金操作。未知权利来源不能通过修改标注洗成可用数据，须先核实来源后以新版本批次重新导入。

## 冻结与训练

“冻结与导出”只取当前批次已确认且证据一致的样本。填写用途、确认使用范围，再生成冻结版本；零确认时禁止冻结。下载需要管理员登录，文件为JSONL。

冻结记录绑定来源SHA-256、审核记录ID、实际审核人和完整内容。分类导出兼容现有TicketSample；其他三类保留original与annotation。旧快照不可修改；后续更正追加新审核记录，旧文件仍可追溯，但不能继续支撑新的模型审批，已经配置的受管模型也会回退人工。

在本项目目录，用新文件名保存分类导出并执行：

```powershell
.\.conda\python.exe -X utf8 -m nlp.cli prepare --data data/reviewed/classification-v1.jsonl --purpose formal --out artifacts/runs/reviewed-v1/split.json
.\.conda\python.exe -X utf8 -m nlp.cli train-baselines --data data/reviewed/classification-v1.jsonl --manifest artifacts/runs/reviewed-v1/split.json --out artifacts/runs/reviewed-v1/baselines
```

formal数据校验、相似归组、训练/验证/测试固定切分和验证集选阈值沿用现有实现。生成产物仍是deployment_approved=false，需要单独审批。fastText/BERT训练和对照入口保留，当前管理中心可发布的在线推理包仅RF/LR；没有把其他模型的smoke成绩当作正式上线证据。

检索独立复核后可直接指定数据库中的冻结ID重跑四策略，必须用尚不存在的报告路径：

```powershell
.\.conda\python.exe -X utf8 -m rag.evaluate --review-snapshot 123 --out artifacts/evaluation/retrieval-reviewed-v1.json
```

该命令验证快照类型及当前审核版本，将人工相关性/拒答判定与原问题组合，绑定冻结指纹并实际执行BM25、vector、hybrid、rerank。评测中发生更正会中止。零可回答样本的Recall/MRR返回null。没有调用百炼，也没有把查询相关性审核自动当成政策正确性或生产发布许可。123只是命令示意，当前业务库没有真实人审冻结ID。

## 登记、审批与部署

在“模型审批”选择分类冻结版本、训练产物与范围，登记候选。服务不接受任意上传pickle，只读取管理员控制的artifacts/runs目录；拒绝绝对路径、路径穿越和越界链接，先检查清单及文件指纹，不在登记时反序列化。

| 检查 | 影子验证SHADOW | 正式自动分流LIVE |
|---|---|---|
| 数据与来源 | 正式模式、真实复核记录、当前冻结版本、六类映射、同一数据和切分哈希 | 相同 |
| 运行产物 | RF/LR完整目录、模型内容哈希、训练与推理依赖版本一致 | 相同 |
| 最少样本 | 18条，仍只供影子验证 | 1200条 |
| 独立测试 | 固定切分；不据小集宣传质量 | 测试至少120条，Macro-F1≥0.80 |
| 自动接收策略 | 强制人工；保留candidate_label和scores | 阈值启用，测试接收准确率≥0.90，覆盖≥20% |

这些是本参考项目实现的发布门槛，不是企业通用标准或生产效果保证。不能靠扩大合成样本或自行修改报告来替代人工复核和独立质量审查。

审批人核对证据、填写理由并勾选确认。任一门槛失败则不能批准；产物被改、损坏或删除也会阻止批准。成功后创建独立UUID发布目录 `artifacts/governance/releases/release-ID-UUID/manifest.json`，不改原训练目录；记录审批人、时间、数据快照、范围和内容指纹。可拒绝候选或撤销已批准版本，均有审计与版本冲突校验。

批准只生成可审核的发布包，不自动改配置。部署人员检查后在私有.env设置SMARTTICKET_CLASSIFIER_MANIFEST为该包的实际绝对路径，再运行 `.\.conda\python.exe -X utf8 -m scripts.local_services restart`。取消配置可回到默认人工兜底。没有人审数据时不要执行这一步。

在线分类接口和worker均先查受管审批账本，再校验与加载包；完成推理和自动派单前还复查审批。撤销或更正导致审批失效后，新分类走人工；已完成的历史派单不自动追溯改写。影子包始终label=null/needs_manual_review=true，不自动派单。旧版管理员自己配置、位于受管目录外的可信清单保留原信任边界，不宣称它已有本中心审批；capabilities会区分配置待验证、影子、正式和失效状态。
