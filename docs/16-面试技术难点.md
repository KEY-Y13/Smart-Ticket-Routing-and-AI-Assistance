# 面试讲解与证据边界

可以陈述：在虚构3C售后场景实现模块化单体，连接真实MySQL、Vue工作台、确定性派单、SLA和证据审核链路；完成四模型同切分smoke、GPU参数更新/重载、真实混合检索与重排、权限/并发/故障测试。不能陈述：已服务真实企业、正式数据达到1200条、BERT生产准确率、客服效率提升百分比或真实LLM回复质量已通过。

| 追问 | 应解释的因果链 | 代码/证据 |
|---|---|---|
| 为什么模块化单体？ | 事务跨工单/负载/审计，当前团队与数据规模不需要微服务；模型独立进程避免依赖/内存耦合 | backend/app/services、rag/worker |
| 为什么TF-IDF不能先fit全量？ | 词表/IDF会看到测试分布，验证/测试只能transform；相似组也必须在切分前识别 | nlp/data、baselines/train |
| 为什么BERT没胜过RF？ | 仅48条训练、12条测试、1epoch/6个优化步；流程正确不等于数据与训练充分，不能靠改测试集追高分 | comparison.json中的BERT低分 |
| BERT维度如何走？ | `[B,L]` token/掩码 → `[B,L,768]` → 句表示 → `[B,6]` logits；CE对正确类别负log概率，padding不参与有效注意力 | nlp/bert/train.py |
| 累积4步是否等价大batch？ | batch2近似有效batch8，但dropout、优化步/调度和尾批处理要一致；AMP/checkpoint降低显存，有计算代价 | BERT配置与资源记录 |
| Softmax 0.9为何不等于九成正确？ | 它是相对分数；验证集选阈值并看覆盖率/误收率，正式数据不足时不能部署 | threshold_policy、ArtifactClassifier |
| 纯向量召回已经1.0，为何还做混合？ | 单一演示集不能代表企业术语/新型号；本批混合确有下降，保留负面结果，不能预设技术堆叠一定有效 | retrieval-demo.json |
| 为什么还要Reranker？ | 双塔压缩交互，cross-encoder处理候选细粒度条件；MRR提升但CPU延迟到约1.9秒，吞吐代价明确 | worker与四路报告 |
| 索引不是事实源是什么意思？ | 索引是可重建派生物，文档版本/有效期由DB控制，候选与发送前都再检查 | knowledge.py、assistant.py |
| 有引用为何仍不可信？ | 可能引用不支持当前问题、失效，或截掉否定词；完整chunk、时效校验与人工审核共同限制风险 | llm.validate_output、发送校验 |
| 为什么不让模型直接查SQL？ | 模型不能决定资源权限或资金变更；由已授权业务查询固定字段，SQL参数化，模型无执行工具 | business.py、数据库表权限 |
| 怎样防容量超卖？ | 全局互斥行+事务内重查、稳定策略、条件唯一约束，多请求竞争最后容量；SQLite测试不足以证明 | tests_mysql |
| 幂等与版本锁何不同？ | 幂等识别同一业务请求重放，版本锁拒绝过时修改，唯一约束保护最终不变量；三者不能互相替代 | tickets.py、DB constraints |
| 服务挂了SLA会漏吗？ | 截止和提醒键都持久化，重启再扫描；不是只靠进程内定时器 | operations.py、SLAAlert唯一键 |
| 反馈为何不自动训练？ | 人工修改仍可能误判、受提示影响或不满足来源许可，需要独立复核与去泄漏再入训练集 | AIFeedback.approved_for_training |
| 怎么证明备份能用？ | 真正恢复到新库，按主键稳定排序比较全部表行数和哈希；仅生成SQL文件不算恢复 | backup-restore.json |

展示时先演示一个具体问题：客户耳机无声→分类/派单→授权业务查询→有效政策→修改审核→发送→解决/关闭。再展示一个失败：停用知识或补充新消息后旧草稿拒发。最后打开真实实验的错误案例，解释为什么正式模型仍未批准。

简历表述可采用“实现基于角色与资源归属的工单分流及证据草稿审批，使用固定合成场景验证混合检索、SLA恢复和MySQL并发不变量”。如果要写数字，注明数据来源、测试规模、运行环境和分母；不要把12条测试的Macro-F1写成生产准确率。

局限必须主动说明：正式人审数据不足；本机百炼已授权启用但预算60，Docker默认关闭；旧Torch仅实验；粗粒度锁限制吞吐；检索门槛未独立校准；外部通知/真实资金操作未接入；Docker以实机日志为准。

新增可追问的实际改进：统计接口原先按工单/反馈逐行发SQL，改为分组计数与关联查询，并用0条/20条输入证明SELECT次数不随行数增长。运行状态区分API、后台心跳、检索、索引和任务积压，真实停止/恢复演练没有修改时间戳凑通过。HTTPS验证拒绝不可信CA和错误主机名，但本机测试CA没有装入系统信任，不冒充公网证书。具体数值、代码和复跑命令见21文档。
