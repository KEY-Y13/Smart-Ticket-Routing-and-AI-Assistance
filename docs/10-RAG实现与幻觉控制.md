# RAG 草稿、证据与人工反馈

入口：`services/knowledge.py`、`assistant.py`、`llm.py`、`schemas/intelligence.py`。链路：角色/工单归属 → 授权业务查询 → 客户问题与历史 → 有效知识检索 → 保存输入版本/事实/证据 → 待审核草稿 → 人工反馈 → 独立发送。失败不自动发送。

默认“证据摘录”真实执行混合检索和重排，组合完整政策原文与受控订单记录，**不是LLM输出**。无充分依据409，检索服务/索引异常503，业务权限不足403，不伪造内容。

当前LLM供应商改为阿里云百炼，默认qwen-plus，使用HTTPS Chat Completions兼容接口、JSON Object输出及enable_thinking=false。API Key从SMARTTICKET_LLM_API_KEY或DASHSCOPE_API_KEY读取，无SQL/执行工具，无隐式重试。固定schema只允许客户原文中的连续诉求/商品/时间span、已有chunk_id及逐字引用、缺失信息枚举、必须为true的人工确认。未知字段、非原文实体、伪造引用、坏JSON、截断均拒绝。呈现完整chunk，防止截掉“不得”或前置条件而逆转政策。业务状态由服务端授权查询呈现，LLM不自由编写交易事实。

用户文本与文档是不可信数据。系统指令不接受其中的角色和工具指令；导入阻断明显注入模式，输出再做Pydantic和原文校验。关键词不是完整注入防线，核心是无工具权限、受约束输出、服务端事实与人工审核；有引用也不等于适用。

AISuggestion保存原始输出、Prompt/模型版本、证据、事实、输入版本与上下文哈希。AIFeedback另存最终人工文本、原因、知识错误和审核人，默认approved_for_training=false。采纳不等于发送；发送重查权限、工单输入版本、业务事实和知识有效期，陈旧草稿要求重做。消息与草稿状态同事务提交，重复发送不会新增第二条。

用户本轮已授权付费调用，本机启用百炼并设60次总预算；新安装和Docker示例仍默认禁用。先持久化调用预留，失败或结果未知也占预算，不自动重试。真实MySQL已验证两请求竞争最后一个额度时，仅一个进入模型调用，模拟失败仍占额度。日志不记录密钥、Prompt全文或客户正文。

50条 `reply-contract-scenarios.jsonl` 是明确构造的安全fixture，运行 `python -m scripts.evaluate_reply_guards` 验证伪造引用、实体和任意SQL字段。它们不是模型生成回复，不代表LLM质量。超时、429、非JSON和截断通过MockTransport验证适配器错误路径；真实模型语义/措辞评测尚未执行。

百炼接入配置、地域与剩余验收见[百炼接入与剩余验收](18-百炼接入与剩余验收.md)，真实调用及失败分析见[本轮验收](19-真实百炼验收与恢复演练.md)。预算是每个数据库实例的持久化上限，不是跨所有部署/账号的云端消费上限。
