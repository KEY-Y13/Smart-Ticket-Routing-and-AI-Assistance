# 百炼接入与剩余验收

更新日期：2026-11-07。参考代码和已执行的运行验收已经交付，但正式业务质量与生产条件尚未全部验收。用户随后明确授权打开付费调用，本机已启用阿里云百炼，工程总预算设为60次。完整实测见19-真实百炼验收与恢复演练.md。

## 当前模型配置

| 项目 | 当前值 |
|---|---|
| 供应商与模型 | 阿里云百炼 / qwen-plus |
| 北京兼容接口BASE_URL | https://dashscope.aliyuncs.com/compatible-mode/v1 |
| 协议 | POST /chat/completions，非流式，JSON Object，enable_thinking=false |
| 密钥来源 | 同一配置来源中SMARTTICKET_LLM_API_KEY优先于DASHSCOPE_API_KEY；来源按环境变量、私有.env、secret顺序读取 |
| 本机启用开关 | SMARTTICKET_LLM_ENABLED=true |
| 本机调用总次数预算 | SMARTTICKET_LLM_CALL_BUDGET=60，失败也占预算 |
| 无LLM时的功能 | 真实检索、证据摘录、人工审核、独立发送仍可用 |

不使用OpenAI API Key，也不使用DeepSeek官方API的默认地址或模型名。程序直接使用现有HTTPX依赖调用百炼兼容接口，没有为了更换供应商新增SDK或全局安装。

本机DASHSCOPE_API_KEY存在于用户环境变量，当前北京端点与qwen-plus真实请求已成功，证明本次调用所需鉴权和权限可用；不据此保证未来额度。未展示或复制Key到公开文件；项目.env修改前备份在.mysql-local/config-backups。不要将真实Key发到聊天或提交仓库。

百炼官方推荐业务空间专属域名，例如https://YOUR_WORKSPACE_ID.cn-beijing.maas.aliyuncs.com/compatible-mode/v1；现有dashscope域名仍受支持，因此在未取得业务空间ID时保留可用的北京公共域名。若Key属于其他地域，须将SMARTTICKET_LLM_BASE_URL改为该地域控制台提供的地址，不能混用地域。qwen-plus别名会随平台更新，正式评估须记录实际模型返回版本或改用已验证的快照ID。

JSON Object模式只保证JSON格式，不保证符合业务schema；本项目仍执行Pydantic、客户原文span、文档ID及逐字引用校验，并要求人工确认。保留1200输出Token上限以限制单次输出；官方结构化输出文档建议避免max_tokens导致截断，本项目若发生截断会明确失败，不使用部分JSON、不重试、不发送消息。后续真实评估需要检查该上限是否适合实际场景。

离线适配测试覆盖：目标百炼地址、Bearer头、模型名、关闭思考、JSON模式、无工具权限、缓存Token统计、401/403/429/500、超时、坏JSON、截断、伪造实体与引用，以及禁用时完全不发送请求。测试使用显式MockTransport，不能称为百炼真实调用验收。

当前本地服务已启用并通过真实百炼浏览器流程；百炼业务代码新Docker镜像也已构建，LLM适配源码哈希与宿主一致，真实检索和容器浏览器复验通过。Docker默认仍禁用付费，防止独立数据库预算另开；所有真实模型调用发生在Windows本机实例。容器验收后Desktop与Ubuntu恢复任务前停止状态，全部27个原容器保留。

## 真正尚未完成的验收

| 项目 | 当前差距 | 完成标准 |
|---|---|---|
| 正式分类数据与上线模型 | 仅72条AI编写、未独立复核的合成文本；原参考规模1200–3000尚未达到；当前模型仅smoke，线上人工兜底 | 取得允许使用的数据，人工复核标签、去重与分组切分；重新训练对比、审查错误与阈值，再批准模型部署 |
| 知识与检索独立真值 | 50篇虚构政策和110条检索样本均由AI编写；当前指标只证明演示集结果 | 业务人员核实政策适用条件与版本，独立标注查询相关性/拒答真值，按冻结数据重跑四策略评估 |
| 百炼正式质量评审 | 已有真实调用、用量、延迟、拒答及对抗记录；未完成独立人工语义质量评审和实际账单核对 | 对冻结案例进行人工评审，区分正确拒答和错误拒答，并核对控制台实际账单 |
| 生产容量与运维 | 4项MySQL并发竞争测试通过，但不是持续负载压测；本机运行不等于公网生产部署 | 依据实际目标定义并发/数据量/延迟门槛，完成压测、TLS与密钥管理、监控告警和备份恢复策略验收 |
| 独立复刻阶段B | 只有学习与复刻指南，尚未由用户独立编写和验收 | 用户按17-独立复刻指南逐阶段实现与解释，AI先审查设计和提供提示 |

真实退款、多租户、Kubernetes、OCR/语音、多平台接入、多智能体和在线自动训练属于原P2明确暂不实现范围，不是遗漏的P0/P1功能。邮件短信、SSO/MFA也未作为本机参考版已经实现的能力宣传。
