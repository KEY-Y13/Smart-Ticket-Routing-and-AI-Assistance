# Reranker 原理与评估

入口：`rag/worker.py` 的rerank分支；来源与哈希在 `artifacts/pretrained/bge-reranker-base/source-manifest.json`。使用官方MIT模型，不在本项目重新微调。

Embedding双塔分别编码query/passage，可预计算文档，速度快，但细粒度条件与否定词易被压缩。Cross-encoder将文本对一起送入序列分类模型，注意力跨两段交互，因此只处理召回候选，不扫描整个大库。

输入B个 `[query, passage]` 文本对，Tokenizer产生 `[B,L]`，L≤384且包含特殊分隔位置；内部表示约 `[B,L,768]`，分类头输出 `[B,1]`。当前批大小4、CPU线程4，按原始logit排序，不把它称为“回答正确概率”。相关性训练可用二元交叉熵或成对/列表排序，难负例质量很关键；本项目当前没有这个训练损失。

证据门槛暂用最高logit≥0，是未经正式领域校准的运行规则。10条演示无答案样本均未通过，只证明这10条的行为，不能保证任意领域外问题或攻击都被识别。仍需人工核查引用是否适用。

实测混合MRR@5约0.921，重排约0.956，Recall@5均为0.99。CPU重排P50约1793ms、P95约1905ms，纯混合约41/62ms。属于本机已加载模型的演示查询，不含冷启动/索引构建，不代表Docker或生产并发性能。

正确文档若不在前20个融合候选，重排救不回来；长文本截断丢条件时应改解析/切块。替代方案为更小cross-encoder换延迟、领域难负例微调、纯向量低延迟或BM25术语匹配。是否增加重排取决于实测收益和资源成本。

验证：同一评测集对照四路排名、拒答与P50/P95。追问：为什么不全量cross-encoder？pair如何截断？负logit是否等于不相关？如何发现重排改善MRR但没有改善Recall？
