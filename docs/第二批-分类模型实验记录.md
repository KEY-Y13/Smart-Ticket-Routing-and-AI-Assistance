日期：2026-11-06。当前证据范围始终是 `synthetic_pipeline_smoke_only`，不属于正式数据评估或生产效果。

- 已固定 revision 的中文 BERT safetensors 本地加载，全编码器和分类头参与 GPU 微调。

## 实际运行入口和报告

完整编排：`scripts/run_models.cmd --device cuda --epochs 1`。

本轮最终报告：`artifacts/runs/models-smoke-20261106T090400207026Z/comparison.json`。其下 baselines、fasttext、bert 分别保存完整实验产物，step-0..4.log 保存各阶段输出。旧的首批报告和单独试跑未覆盖。

数据仍为同一批 72 条 AI 编写、未人工复核的样例，按组切分为 48/12/12，每类测试仅 2 条。没有新增“人工已审核”记录，也没有因为 BERT 分数低而改标签、换测试集或继续调测试集。

| 模型 | 测试 Accuracy | 测试 Macro-F1 | 预热 P50/P95 ms | 设备 |
|---|---:|---:|---:|---|
| TF-IDF RF | 0.916667 | 0.911111 | 7.184 / 10.319 | CPU |
| TF-IDF LR | 0.916667 | 0.911111 | 1.105 / 1.291 | CPU |
| fastText 字级 | 0.750000 | 0.683333 | 0.0276 / 0.0317 | CPU |
| 中文 BERT | 0.250000 | 0.171717 | 20.869 / 25.718 | RTX 3060 Laptop |

以上是具体一次运行的流程验证数值，**不能形成模型优劣、业务准确率或生产速度结论**。BERT 的计时还含 tokenizer、传输、softmax 和评估 loss，不能和 CPU 行直接做公平速度比较。

BERT 本轮仅 1 epoch、6 次优化器步尝试，训练 loss 约 1.842428；不是充分收敛实验。多数测试样本被预测为退款类，是需要保留的失败现象，而非应掩盖的报错。可能与训练量/步数不足、样本分布、初始分类头等有关，这些是待进一步通过正式数据和验证集实验区分的假设，不是已证明原因。

验证集选出的 BERT 阈值仅接收 1/12 条样本，虽然该子集经验正确率为 1.0，但没有统计可信度。不能把它表述成“BERT 100% 准确”。所有模型仍 `deployment_approved=false`。

## 资源记录

本轮 BERT CUDA peak allocated=1,875,894,784 bytes，reserved=1,952,448,512 bytes；进程峰值工作集=2,072,809,472 bytes。分配器峰值不等于总显存，工作集也不能直接与 GPU 分配相加作为统一内存指标。

fastText worker 峰值工作集=192,036,864 bytes，包含原模型和重载模型共存及解释器/库。RF/LR 内存峰值仍未测，不补造数值。

运行环境实测为 torch 2.5.1+cu121、Transformers 4.57.6、NumPy 2.5.4；fastText 独立使用 NumPy 1.26.4。新版 Torch 下载未完成，当前旧版仅为已验证的本地 smoke；部署维护版本仍须重新评审。具体来源和版本锁见 `环境与实验运行.md`。

## 学习顺序

先读 `05-TFIDF与fastText对照实验.md` 理解 64 维浅层表示、native 标签排序与 Macro-F1；再读 `06-BERT原理与微调.md`，沿 encode → loader → forward → cross_entropy → backward → optimizer → validation → reload 逐步跟踪。

至少能独立解释：为什么同一模型要保存 tokenizer、为什么补零要 attention mask、为什么最后不足一个 batch 的累积需要按样本数计算、为什么验证集 1 条正确不是 100% 可用、为什么 tiny 单元测试不能冒充中文预训练实测。
